> 据 AIToolsRecap 7 月 19 日报道，OpenAI 收购德国初创公司 Ona（前身即开源云开发环境 Gitpod），旨在为 Codex 编程工具提供持久云端 Agent 运行能力——支持任务在用户关闭笔记本后继续运行，解决当前编程 Agent"会话结束即任务停止"的最关键限制。Codex 周活用户已突破 500 万，Ona 的云环境基础设施使大规模重构、测试套件生成、文档化等长时任务可在云端 7×24 运行。交易条款未披露，但这是 2026 年 7 月 AI 编程工具领域第三笔重大整合：此前 SpaceX 已以 600 亿美元收购 Cursor 母公司 Anysphere（6 月），Anthropic 于 7 月 16 日推出 Ode 前置部署型企业 AI 工程师服务。

> **🔹 3. Grok Build Data Leak: xAI CLI Uploaded Repositories, SSH Keys, and Password Databases Without Permission（Grok Build 数据泄露：xAI CLI 未授权上传用户代码库、SSH 密钥与密码数据库）**

> 📝 **摘要**

> 据 AIToolsRecap 7 月 19 日报道，AI 安全研究员 Cereblab 披露：xAI 的命令行工具 Grok Build 将用户整个代码仓库（含完整 Git 历史）上传至 Google Cloud Storage bucket，即便用户明确指示不要打开文件亦然；至少一名用户的整个家目录被上传，包括 SSH 密钥与密码管理器数据库。马斯克随后承诺"数据清理"，但 SpaceXAI 截至 7 月 19 日未发布事故报告、未确认数据是否被任何人访问、未确认受影响用户数量、未确认当前版本是否已修补。安全研究界强调："数据清理承诺不是安全补救措施，不回答风险评估所需的核心问题。"

> Cereblab 建议任何在含 SSH 密钥、密码管理器数据库或敏感代码库的机器上运行过 Grok Build 的用户立即采取三项行动：轮换 SSH 密钥、更改受影响机器上密码管理器内所有账户密码、审计 Git 历史中硬编码的凭据；在 SpaceXAI 发布完整事故报告与补丁确认前，不要在敏感代码库上恢复 Grok Build 使用。这是 AI 编程/Agent 工具"自动越权访问"风险的标志性事件，与同期 Sysdig 披露的全自主 AI Agent 勒索软件 JADEPUFFER、蚂蚁密算 HOP 3.0"智能体原生语言"防御架构形成全球"攻击-防御"对照——AI Agent 自主化在工具层与攻击层同时放大风险，企业级 AI 编程工具采购需将"权限模型+沙箱隔离+凭据保护"列为前置审计项。
